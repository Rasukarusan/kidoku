# コレクションモデル

## 対象範囲

DBは本・映画などの種類、コレクションへの所属、複数の履歴を管理する。
Webは読書記録・本棚・本の詳細・検索モーダルのUIとURLを使用する。
汎用モデルの操作はGraphQL、PAT、MCPを通じて提供する。

## 保存先

| テーブル                | 責務                                                             |
| ----------------------- | ---------------------------------------------------------------- |
| `collections`           | ユーザーごとの名前、説明、表示順                                 |
| `item_types`            | 種類のキーと属性・履歴のJSON定義                                 |
| `items`                 | 所有者、種類、タイトル、画像、カテゴリ、総合評価、メモ、固有属性 |
| `collection_items`      | コレクションとアイテムの多対多の所属                             |
| `item_logs`             | 読了・鑑賞などの日時、メモ、評価                                 |
| `item_templates`        | 種類と属性を持つ登録テンプレート                                 |
| `collection_highlights` | コレクション内のお気に入り順位                                   |
| `item_comments`         | アイテムへのコメント                                             |

アイテムとコレクションはユーザーごとに所有する。所属先と対象の所有者は一致させる。
未所属・履歴なしのアイテムも保持できる。
コレクション削除では所属のみを削除し、アイテムと履歴を残す。
アイテム削除では所属、履歴、コメントなどの関連データを削除する。
所属操作と削除はトランザクション内で整合性を保証する。

## 種類と履歴

種類は `book` と `movie` を初期定義とする。
本の固有属性は `authors` / `isbn`、映画は `directors` / `releaseYear` / `runtimeMinutes`。
属性の型、必須条件、上限、利用できる履歴の種類は `item_types.definition` に定義し、APIで検証する。
DBには実行コードを保存しない。外部検索・AI処理は許可済みのハンドラーを使用する。
属性定義の変更には `attributes_version` に対応する変換を用意する。
種類の直接変更は許可しない。

再読・再鑑賞は同じアイテムへの履歴追加として扱う。
アイテムの総合評価と履歴の評価は独立させる。
日時未設定の履歴は日付不明として保持し、年・月別の集計に含めない。
件数はアイテムIDで重複排除し、履歴の回数と区別する。
読書分析は `book` と `read` の履歴を対象とする。

## 読書画面への接続

画面URLは `/:user/sheets/:name`、`/:user/sheets/total`、`/books/:id`。
検索・登録は本の検索モーダルを使用する。
Book / Sheetの読み取りは共通パッケージ `@kidoku/reading-store` が汎用テーブルから画面用のデータを生成する。
絞り込み・並び順・ページングはDBで処理する。書き込みも汎用テーブルを使用する。

Book APIの対象は本に限定する。
互換Bookのシートは所属IDの最小値、読了日は最後に追加した読了履歴を投影する。
複数所属、履歴全体、未所属アイテムは汎用APIで扱う。
WebとAPIのPrismaスキーマは一致させる。

## 公開範囲

アイテムメモはアイテム単位の公開設定に従い、履歴メモは所有者だけに返す。
所属先を変えてもメモの公開範囲は変わらない。
他ユーザーによる所属追加・更新・削除を拒否する。
検索インデックスとエクスポートには、呼び出し元が参照できる情報だけを返す。
MCPの汎用読み取りには `items:read`、本の読み取りには `books:read` を使用する。

## DB運用

初期化は空DBだけを対象とする。
データのあるDBには、書き込み停止と復元検証済みバックアップの取得後に移行スクリプトを適用する。
`prisma db push` は使用しない。
適用後は件数・ID・所有者・所属・メモ・購入参照とスキーマを検証する。
手順は [COLLECTION_MIGRATION.md](./COLLECTION_MIGRATION.md) を参照。
